Workspace

forge ships as a 5-crate runtime workspace. Only forge-tui renders to the terminal; the other four layer underneath through strict acyclic dependencies. forge-test-harness is the wire-conformance harness — not in the runtime path.

forge-primitives

Wire-shape types shared across forge-* crates. Message envelopes, content blocks, hook/permission/option/subagent data, render-side views, channel commands, IDs. No logic, no I/O, no async.

depends on: nothing forge-shaped

forge-sdk

Wraps the claude CLI subprocess. Owns the stream-json codec, transport, control dispatch, in-process MCP host, callback registries, and Options builder.

depends on: forge-primitives

forge-agent

Drives one forge-sdk Client behind a channel-based Agent / AgentHandle API. Owns userdata (settings, trust, sessions catalog, memory, plugins), cloud (oauth/usage/account), env (git context), translate, and tooling.

depends on: forge-primitives, forge-sdk

forge-workspace

Multi-session orchestrator and TUI-facing facade. Per-session DomainSession holds operational state; per-session SessionTask actors pump AgentHandle::take_events() into SessionUpdates and route Commands back. The single point of contact between TUI and the agent layer.

depends on: forge-primitives, forge-agent

forge-tui

Native ratatui terminal interface. Pure view layer; consumes SessionUpdate and dispatches Command via forge-workspace. Holds per-session UiSession for presentation state (messages, viewport, input editor, hover hints). The subject of this map.

depends on: forge-primitives, forge-workspace

forge-test-harness

Wire-conformance harness. sdk_wire scope (forge-sdk ↔ claude CLI). Replay-based offline tests + opt-in live capture. Not in the runtime path.

depends on: forge-sdk (transitively gets forge-primitives)

Layout

forge-tui's main frame is a strict vertical stack composed by layout::compute, flanked by inline side panes at the wider tiers. This stack only renders in ActiveView::Chat. When the user opens /config, the resume picker, or hits the trust gate, forge swaps the entire frame to a single full-screen overlay (ActiveView::Config, ActiveView::SessionPicker, ActiveView::Trusted) — chat / input / side panes all disappear during those views. At terminal widths ≥160 cols the chat frame is flanked by a 40ch Projects pane on the left (carrying the account / mode / model / usage / location panel at its bottom) and a 40ch Inspector pane on the right (carrying the live TASKS list from TodoWrite); between 120–159 cols both panes shrink to 30ch with truncation; below 120 cols a single-row top bar replaces both panes — tapping the ▤ icon (or Ctrl+B) opens the Projects overlay, tapping ▦ (or Ctrl+E) opens the Inspector overlay.

In ActiveView::Chat the central stack is:

  1. body — chat scrollback (Min 3 rows, takes the flex)
  2. input_sep — full-width ─ separator (1 row, DIM)
  3. input — input field (1 row, grows up to N as user types)
  4. input_bottom_sep — full-width ─ separator (1 row, DIM)
  5. help — help overlay (0 when inactive, else HELP_PANEL_HEIGHT = 14)

The mode / model / fast-mode / cwd / branch / usage status used to sit as 2 rows below the input; that row is gone. Mode / Model / Fast / Effort / usage moved to the Projects pane's bottom panel together with the account name and a per-window usage bar (5h, 7d); cwd and branch moved to the right-hand Inspector pane's GIT section (which also surfaces the per-file diff stats). The live todo list used to sit above the input as the todo panel (closed = 1-line compact, open = up to 5 rows, toggle on Ctrl+T); that panel is gone too — todos now render in the Inspector pane as its TASKS section.

Multiple sessions = multiple forge processes, each in its own terminal pane. There is no in-process coordinator view today. Multi-session is the direction we're heading; see the final section.

Projects pane (Wide / Medium / Narrow tiers)

visible: at all terminal widths — Wide (≥160) renders a 40ch inline pane, Medium (120–159) a 30ch inline pane, Narrow (<120) a single-line top bar with on-demand full-screen overlay

Left-side pane, 40ch wide, docked to the left of the chat frame. Lists projects from forge.toml's [[projects]]. Each project renders as a single bold row; the active project is in RUST_ORANGE bold, background projects use the terminal's default fg + bold. The active project's drilldown (only) renders its sessions immediately beneath: lead first (◆), extras after, with the currently-viewed session marked •. Sort is most-recently-active first; alphabetical tie-break.

Project rows are mouse-only; chat input keeps keyboard focus. Click any project header to switch the active session to that project's lead — if the lead is already in-process, the swap is instant; if the project is sleeping (no in-process session yet), the click hands off to workspace.get_agent_handle(SessionTarget::Named(name)) and a synthetic __spawn_<project>__ bucket fronts a "Waking…" placeholder welcome until Connected arrives and migrates the bucket onto the real session UUID. The pane has two anchored regions: the project list grows from the top, and the account / status panel is hard-docked at the bottom. The dim ─ rule between them sits at a fixed row from the bottom — a permanent gutter, not a separator that floats based on list length. The two never overlap. When the project list outgrows its region the list scrolls within itself; the panel never gives up its rows. The empty space above the rule in the mockup above shows what a short project list looks like — the panel still sits at the bottom, gravity is preserved.

The panel's job is to read like account chrome, not "current status." Even though Mode / Model / Ctx flip when the user switches to another session in another project, the panel's shape, position, and labelling stay put. The Profile line at the top of the panel is the anchor — when you switch from your Stargate account's forge session to your Gateway account's data-modules session, Profile flips and Mode / Model / Ctx flip with it, but the panel itself doesn't move. The panel renders, in order:

  • Identity / posture — Profile (active account display name from forge.toml's [[accounts]], via app.active_account_display_name), Mode (permission mode badge — same colors as the old footer used: auto / acceptEdits yellow, plan blue, bypassPermissions / dontAsk red, default dim), Model (display name with the (… context) wrapper stripped, e.g. Opus (1M context) → Opus 1M — only in the panel; other surfaces keep the raw name), Effort (always shown on its own row so a long model name can never push it off-screen), Fast (off / cd / on, same colors as the old FAST:* badge).
  • Usage bars — three 12-cell filling bars: Ctx (per-session context %), 5h (5-hour plan window), 7d (combined 7-day window). The fill colour is a per-cell position gradient, not a threshold step: cells 1–3 green, 4–6 yellow, 7–9 orange, 10–12 red, so the rightmost filled cell tells you which zone the bar is in. Empty cells stay ░ in DIM. The 5h and 7d rows are followed by a DIM, right-justified duration on the next line (e.g. 1h 48m / 4d 4h) — the legacy resets in prose was dropped so the eye lands on the time, not the verb. A single blank row separates each bar group from the next.
  • Versions — two trailing rows: forge (the running binary's CARGO_PKG_VERSION) and claude (the version reported by claude --version on the local machine). When the npm registry probe finds a strictly-newer published version under the @anthropic-ai/claude-code latest dist-tag, a yellow ↑ vX.Y.Z indicator appends to the claude row. Probes run once at app startup in parallel via Workspace::fetch_cli_version_info; missing values render as — so the row count stays constant.

The 📁 cwd and ⎇ branch rows that used to sit at the bottom of this panel moved to the right-hand Inspector pane's GIT section.

The pane is vertically split into two anchored regions: top for the project list, bottom for the account / status panel. The panel reserves a fixed 17 rows from the bottom up (rule + 5 identity rows + 1 blank + 1 Ctx bar + 1 blank + 2 (5h bar + ETA) + 1 blank + 2 (7d bar + ETA) + 1 blank + 2 version rows). Inspector pane (Wide / Medium / Narrow tiers)

visible: at all terminal widths — Wide (≥160) renders a 40ch inline pane on the right of chat, Medium (120–159) a 30ch inline pane, Narrow (<120) an Inspector ▦ icon on the top bar with on-demand full-screen overlay

Right-side pane, 40ch wide, docked to the right of the chat frame. Mirror of the Projects pane on the left in chrome (banner + rule), Narrow-tier overlay semantics, and persisted-visibility model. The horizontal layout is asymmetric on purpose: the left pane has a │ separator + 1-col padding between it and the chat column; the right pane sits flush against the chat column, using the chat's own scrollbar rail (▕) as the visual divider. The pane's own 2-col content indent provides breathing room from the scrollbar. Reads strictly from the active session — switching projects via the left pane swaps the Inspector's content alongside it.

The banner (INSPECTOR heading + DIM rule beneath it) is pinned at the top — it never scrolls. Everything below it (starting with the GIT section) is a scrollable body: mouse wheel over the body advances the active session's inspector_scroll_offset by 3 lines per notch, and a vertical scrollbar appears on the right edge whenever the body overflows the visible area. The offset lives on UiSession, so switching away to another session and returning preserves where you were looking, same shape as chat scrollback. Same scroll behaviour applies at Narrow tier inside the full-screen overlay.

The pane carries three sections: GIT (always rendered), TASKS (rendered when the active session has todos or a pending verification nudge), and PROCESSES (rendered when claude's spawned process tree has at least one descendant alive — foreground / backgrounded Bash, Monitor streams, grandchildren like rustc workers, or wire-only CronCreate registrations). DIM ─ horizontal rules separate adjacent sections so each surface reads visually distinct. The chat scrollback no longer surfaces a TodoWrite tool-call card; updates land transparently in the TASKS section. Sections render in order: GIT → TASKS → PROCESSES; each downstream section is hidden when its content set is empty. PROCESSES is a live monitor sourced from sysinfo's descendant walk — when the last process exits the section disappears.

The GIT section shows the active session's cwd, the current branch on its own line, a sub-label row below it carrying the diff context (worktree or vs <default>) with aggregate +N -M totals right-justified, an optional PR #N → closes #M #K row when the scanner resolved an open pull request for the branch, and a box-drawing tree of the top-N changed files grouped by directory. Single-child directory chains fold into one row so paths like crates/forge-agent/src/env/ appear as a single header above their file children. The diff side is polled — git_diff shells out to git --numstat every 10 s for the active session only; a 1 s ticker pokes the drain pump, the rule "snapshot is None OR age ≥ 10 s → fetch" decides whether to spawn a scan. The PR side rides on the same poll but is branch-keyed: the scanner only shells out to gh pr list when the branch name changed since the previous snapshot, so steady-state scans on the same branch reuse the cached PR / closes data for free.

GIT renders one of five shapes, all keyed off UiSession.git_diff_snapshot:

  • No snapshot yet (pre-first-scan window) — only the path row renders. Branch + tree are added once the first poll completes.
  • Not a git repo (GitDiffView::NoRepo) — only the path row renders. No branch, no tree.
  • Clean default branch (GitDiffView::CleanDefault) — path + branch row in DIM with no trailing totals (or yellow HEAD for detached HEAD + clean tree). No tree.
  • Worktree dirty (GitDiffView::Worktree) — path + branch row with right-justified aggregate +TOTAL -TOTAL totals + box-drawing tree of the top-5 modified files + optional +N more overflow.
  • Feature branch clean (GitDiffView::BranchVsDefault) — path + branch in RUST_ORANGE with right-justified branch-vs-default totals + the same tree shape, sourced from git diff <default>...HEAD.

The PR #N row is appended below the diff subtitle whenever the branch has an open pull request resolved by gh pr list --head <branch>. The PR number lights up in RUST_ORANGE (the headline); the PR label, the → separator, the closes label, and the issue numbers all sit in DIM as supporting context. When the closing-issue list would overflow the pane width, fitted issues render in order and the tail collapses to a trailing … (or to a bare → … when not even one issue number fits alongside the chrome). Rows are suppressed entirely when there's no open PR, when the branch is the default branch or detached, when gh isn't installed / authenticated, or when the remote isn't a GitHub repository.

Item glyphs and styles:

  • ✓ green — Completed (text DIM + crossed-out)
  • ▸ RUST_ORANGE — InProgress (text white bold; uses active_form when present, else content; wraps onto continuation lines indented under the glyph)
  • ○ DIM — Pending (text gray)

Only the in-progress item wraps. Completed and pending items truncate with … at the pane's right edge — they're scannable status, not actionable text. At Medium tier (30ch) truncation is routine; at Wide tier (40ch) most items fit.

The PROCESSES section surfaces currently-running work in the active session, sitting below TASKS with its own DIM ─ separator. The data source is path A+: the OS process tree under the spawned claude binary is the source of truth for what's alive; wire-tracked tool calls overlay their description when their raw_input.command substring-matches an OS process's cmdline. Four row kinds appear:

  • Backgrounded Bash — OS process that matched a wire-tracked Bash with run_in_background: true (or claude's CLI auto-promoted foreground Bash). Headline = the assistant's description; detail = the actual OS cmdline.
  • Monitor — OS process that matched a wire-tracked Monitor streaming watcher. Persistent / timeout flags carry through to the metadata row.
  • Process — OS process with no matching wire tool call. Foreground Bash invocations, grandchildren (e.g. rustc workers under a cargo build), or anything that's detached from claude's tool registry. Headline = OS process name; detail = OS cmdline.
  • Cron — wire-only. CronCreate registers a schedule; there's no process to walk. Headline = cron expression; detail = prompt.

Each row renders across two or three lines: a status-glyph headline, an optional └─ continuation carrying the underlying cmdline or cron prompt in DIM, and a └─ metadata continuation carrying kind label · status · flags · memory (e.g. Bash · running · 32 MB, Monitor · running · persistent · 8 MB, Process · running · 256 MB, Cron · recurring · session-only). Rows sort by resident memory descending; a sanity cap of 50 keeps a runaway process tree from blowing the body line count, but the inspector pane itself scrolls (the scrollbar IS the overflow indicator) so the section is no longer trimmed to top-N for display. Memory rendering is tier-gated: Wide (≥36 cols of pane width) shows the · 12 MB suffix, Medium drops it so the metadata fits. Status glyphs:

  • ▸ RUST_ORANGE — InProgress wire-tracked Bash / Monitor (text white bold)
  • ▸ DIM — generic Process row (unmatched OS process; text gray)
  • ⏰ DIM — InProgress Cron (the rare in-flight case)
  • ○ DIM — Pending (about to run / awaiting permission; text gray)

data source
GIT: UiSession.git_diff_snapshot — produced by the agent-side scanner (forge_agent::env::git_diff::scan) which shells out to git rev-parse / symbolic-ref / status --porcelain / diff --numstat, plus gh pr list --head <branch> --state open --json number,url,closingIssuesReferences --limit 1 for the PR row (branch-keyed cache: only invoked when the branch name changed from the previous snapshot — same-branch scans reuse cached pr / closes for free). Polled every 10 s for the active session only — synthetic spawn buckets and pre-Connect buckets skip refresh.
