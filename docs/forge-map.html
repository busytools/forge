Workspace

forge ships as a 5-crate runtime workspace. Only forge-tui renders to the terminal; the other four layer underneath through strict acyclic dependencies. forge-test-harness is the wire-conformance harness — not in the runtime path.

forge-primitives

Wire-shape types shared across forge-* crates. Message envelopes, content blocks, hook/permission/option/subagent data, render-side views, channel commands, IDs. No logic, no I/O, no async.

depends on: nothing forge-shaped

forge-sdk

Wraps the claude CLI subprocess. Owns the stream-json codec, transport, control dispatch, in-process MCP host, callback registries, and Options builder.

depends on: forge-primitives

forge-agent

Drives one forge-sdk Client behind a channel-based Agent / AgentHandle API. Owns userdata (settings, trust, sessions catalog, memory, plugins), cloud (oauth/usage/account), env (git context), translate, and tooling.

depends on: forge-primitives, forge-sdk

forge-workspace

Multi-session orchestrator and TUI-facing facade. Per-session DomainSession holds operational state; per-session SessionTask actors pump AgentHandle::take_events() into SessionUpdates and route Commands back. The single point of contact between TUI and the agent layer.

depends on: forge-primitives, forge-agent

forge-tui

Native ratatui terminal interface. Pure view layer; consumes SessionUpdate and dispatches Command via forge-workspace. Holds per-session UiSession for presentation state (messages, viewport, input editor, hover hints). The subject of this map.

depends on: forge-primitives, forge-workspace

forge-test-harness

Wire-conformance harness. sdk_wire scope (forge-sdk ↔ claude CLI). Replay-based offline tests + opt-in live capture. Not in the runtime path.

depends on: forge-sdk (transitively gets forge-primitives)

Layout

forge-tui's main frame is a strict vertical stack composed by layout::compute. This stack only renders in ActiveView::Chat. When the user opens /config, the resume picker, or hits the trust gate, forge swaps the entire frame to a single full-screen overlay (ActiveView::Config, ActiveView::SessionPicker, ActiveView::Trusted) — chat / input / todo panel / footer all disappear during those views. At terminal widths ≥160 cols the chat frame docks to the right of a 26ch Projects pane; between 120–159 cols the pane shrinks to a compact 20ch with label truncation; below 120 cols a single-row top bar replaces the inline pane and tapping its ▤ icon (or Ctrl+B) opens a full-screen Projects overlay.

In ActiveView::Chat the stack is:

  1. body — chat scrollback (Min 3 rows, takes the flex)
  2. input_sep — full-width ─ separator (1 row, DIM)
  3. todo — todo panel (0 when no todos, else 1 row closed or up to 5 rows open)
  4. input — input field (1 row, grows up to N as user types)
  5. input_bottom_sep — full-width ─ separator (1 row, DIM)
  6. help — help overlay (0 when inactive, else HELP_PANEL_HEIGHT = 14)
  7. footer — 2 rows (primary + context). Hidden in ultra-compact mode (terminal height < 8 rows)

Multiple sessions = multiple forge processes, each in its own terminal pane. There is no in-process coordinator view today. Multi-session is the direction we're heading; see the final section.

Projects pane (Wide / Medium / Narrow tiers)

visible: at all terminal widths — Wide (≥160) renders a 26ch inline pane, Medium (120–159) a 20ch inline pane, Narrow (<120) a single-line top bar with on-demand full-screen overlay

Left-side pane, 26ch wide, docked to the left of the chat frame. Lists projects from forge.toml's [[projects]]. Each project renders as a single bold row; the active project is in RUST_ORANGE bold, background projects use the terminal's default fg + bold. The active project's drilldown (only) renders its sessions immediately beneath: lead first (◆), extras after, with the currently-viewed session marked •. Sort is most-recently-active first; alphabetical tie-break.

Project rows are mouse-only; chat input keeps keyboard focus. Click any project header to switch the active session to that project's lead — if the lead is already in-process, the swap is instant; if the project is sleeping (no in-process session yet), the click hands off to workspace.get_agent_handle(SessionTarget::Named(name)) and a synthetic __spawn_<project>__ bucket fronts a "Waking…" placeholder welcome until Connected arrives and migrates the bucket onto the real session UUID. Click any session row in the active project's drilldown to switch directly to that session.

Tool calls

Every tool invocation renders through the same path: a single title row at column 2 (status icon + kind icon + display title) followed, when there's body content, by lines prefixed with │ (DIM). No bordered cards — Bash, Read, Edit, Grep, etc. all share one shape. The body content varies by tool kind (raw terminal output for Bash, syntax-highlighted code for Read, unified diff for Edit / Write / MultiEdit, etc.).

Standard row (Read · Write · Edit · Grep · Glob · etc.)

visible: any tool call that isn't Bash / TodoWrite / Subagent

Single line: 2-space indent + status icon (success / fail / spinner) in status color + space + tool kind icon (white bold) + space + kind label (white bold — "Read", "Edit", "Bash", etc. from theme::tool_name_label) + space + display title (markdown inline spans, default fg). Body lines (when present) prefix each with " │ " dim (5 chars: 2 + box-drawing-vertical + 2), last line with " └─ " dim (5 chars). If tc.title from claude already starts with the kind label (e.g. claude often sends "Read /path/to/file.rs"), the duplicate prefix is stripped so the column reads cleanly.

Collapsed (when collapse is in effect and the tool call has no diff / pending permission / pending question): the body collapses to a single summary line " └─ <content_summary> click or ctrl+x to expand" (all DIM). The summary text comes from content_summary — last non-empty line of terminal output (capped at 80 chars), or the file name for a Diff, or an MCP resource path, etc.

Collapse precedence: per-tool override (tc.collapsed_override: Option<bool>, set by clicking the tool's row) wins; otherwise the global app.tools_collapsed default applies. Ctrl+X flips the global default — per-tool overrides survive the toggle, so you can keep specific tools pinned in their preferred state. Diff / permission / question short-circuits still keep those interactions visible regardless.

Input area + autocomplete

Input area (default state)

visible: in ActiveView::Chat (hidden when a full-frame view is active). Height grows from 1 row up to MAX_INPUT_HEIGHT = 12 as the user types.

Backed by tui-textarea for cursor / selection / paste-burst handling. The input is sandwiched between two DIM ─ separators (input_sep above, input_bottom_sep below) that chat_view draws. Above the input there's a hint slot that grows the input region's height to accommodate. Possible hint rows (each takes 1+ lines):

  • Prompt suggestion: "Suggestion: <text> Tab to accept" — "Suggestion:" in DIM, suggestion in white, accept-hint in DIM. One line.

When app.status == AppStatus::Connecting, the entire input area is replaced with a spinner + "Connecting to Claude Code..." in DIM (no separators are drawn around it for that variant — the input area takes its own row).

Permission & question prompts

Permission prompt

visible: when the SDK fires a can_use_tool request and forge isn't auto-approving

Inline block appended to a tool-call body in the chat scrollback. Unfocused state: a single dim line "○ Waiting for input... (Tab to focus)". Focused state: blank line, optional display block (header in white bold, description in dim, both indented 2 cols), then a single line of inline options separated by · (middle dot, dim), then a help line.

Each option is rendered as: optional ▸ selection indicator (RUST_ORANGE bold, only on the focused option) + ✓ (green) for allow / ✗ (red) for reject + space + option name (RUST_ORANGE bold when focused, gray otherwise) + dim shortcut hint (Ctrl+y) / (Ctrl+a) / (Ctrl+n).

       Allow Bash to run this command?
         git push origin polish/rate-limit-chip-softer-34

       ▸ ✓ Allow once (Ctrl+y)  ·  ✓ Allow always (Ctrl+a)  ·  ✗ Deny (Ctrl+n)
       ←→ select  ↑↓ next  enter confirm  esc reject

(Permission options come from the SDK's PermissionOptionKind: AllowOnce / AllowSession / AllowAlways / RejectOnce / RejectAlways. Allow variants share (Ctrl+a) for "always" and (Ctrl+y) for "once"; RejectOnce is (Ctrl+n); RejectAlways + plan-mode + question variants don't get a shortcut hint.)

Question prompt (AskUserQuestion)

visible: when the agent asks a structured question

Header line: 2-col indent + ? in RUST_ORANGE + header text in white bold + optional (N/total) progress when there are multiple questions. Question body indented 4 cols (RUST_ORANGE when focused, gray otherwise).
