# Pickers and overlays

## Spinner picker (`/spinner`)

*visible: when `/spinner` (no arg) runs - a transient centered overlay drawn over whatever view is active (chat OR launchpad). `/spinner <name>` sets the style directly without opening the overlay.*

Live picker for the active `SpinnerStyle` - the one source of truth that now drives *every* animated spinner in forge: chat thinking/working, the input box, the projects pane, the inspector TASKS / SUBAGENTS / WORKFLOWS / PROCESSES rows, the in-progress tool-call icon, and the launchpad. The overlay lists all six styles, each row animating at **its own cadence** via the shared time-based frame-index helper, with the live glyph + key + cadence. Moving the highlight is a **live preview**: the whole UI immediately animates with the highlighted style.

Each style's own cadence reads through: `braille` (32ms, 10-frame spin, a full rotation every 320ms), `phase_of_moon` (90ms, ◐◓◑◒), `ember` (160ms, · ✦ ✧ sparkles), `bars_v` (70ms, ▁▂▃▄▅▆▇█ rising then falling), `star` (130ms, ✶✸✹✺ twinkle), `sparkle` (160ms, ✦✧✩✪). Reduced motion floors the fast styles so they slow down. These are design intent, not a guarantee: a style never animates quicker than [`[ui] fps`](./launchpad.md) can paint. That clamp is currently dormant - `braille` at 32ms is the quickest style and the repaint gate never goes coarser than 30ms, so every style runs at its own intent at every accepted `fps`. The cadence shown in the picker is the style's intent.

- **keys** - <kbd>↑</kbd> <kbd>↓</kbd> move the highlight AND live-preview that style across the whole UI · <kbd>Enter</kbd> commit the highlighted style (persist) + close · <kbd>Esc</kbd> restore the style active when the overlay opened (no persist) + close. The overlay is modal - it captures every key while open, over chat and launchpad alike. Keyboard-only for v1.
- **persistence** - The picker's <kbd>Enter</kbd> and `/spinner <name>` both write the choice to the machine-local redb store (under forge's app-support dir; never the hand-authored `forge.toml`). At the next boot the stored override layers over the `[ui] spinner` default, which falls back to `braille`. The in-session active style is `App::spinner_style`; the store write only affects later launches.
- **code** - `crates/forge-tui/src/app/spinner_picker.rs` (state + key handling: open / preview / commit / cancel) · `crates/forge-tui/src/ui/spinner_picker.rs::render` (centered overlay) · per-row glyph via `App::spinner_glyph_for` + the shared `ui::spinner::spinner_frame_index` · `/spinner` handler at `crates/forge-tui/src/app/slash/executors.rs::handle_spinner_submit` · style enum + `from_key` / `ALL_STYLES` / `cadence_ms` in `forge_workspace::ui::SpinnerStyle` · persist via `forge_workspace::Workspace::persist_spinner` → `account_cache::store_spinner`.
- **color** - border + selection marker (`▶`): RUST_ORANGE · highlighted row (glyph + key + cadence): RUST_ORANGE bold · unselected glyph: default fg · unselected key/cadence + footer hints: `DIM`.
- **scope** - Fully transient - the open/highlight state doesn't survive a session restart (only the committed style persists, via the store). Works identically from chat and the launchpad.

## Model picker (`/model`)

*visible: when `/model` (no arg) runs AND the session advertises models - a transient centered overlay drawn over whatever view is active. A session with no advertised models keeps the current-model info line instead; `/model <id>` switches directly without the overlay.*

Pick the session's model from one overlay. The rows are the session's available models - the curated OpenRouter catalog (tiered ten with benchmark, price and context in each row's description) on an `openrouter` account, the CLI-advertised regular models elsewhere. The pseudo `default` row the CLI lists is hidden - the same filter the `/model` argument autocomplete applies. The overlay opens with the highlight on the running model (matched against the model's requested id, then its resolved id) and a `●` marker beside it; descriptions clip at the overlay edge.

- **keys** - <kbd>↑</kbd> <kbd>↓</kbd> move the highlight (wrapping) · <kbd>Enter</kbd> switch the session to the highlighted model and close · <kbd>Esc</kbd> close without switching. The overlay is modal - it captures every key while open, and clicks behind it are ignored (the guard is shared by every picker overlay, so a pane click cannot switch the active session under an open modal). Keyboard-only.

The rows snapshot carries the session they came from; if the active session changed between open and commit, the commit is refused with a visible notice instead of dispatching.
- **code** - `crates/forge-tui/src/app/model_picker.rs` (state + key handling: open / move / commit / cancel) · `crates/forge-tui/src/ui/model_picker.rs::render` (centered overlay) · `/model` handler at `crates/forge-tui/src/app/slash/executors.rs::handle_model_submit` with the shared switch at `switch_model` · rows from the session's `available_models`, which `crates/forge-workspace/src/session_task.rs::merge_catalog_models` swaps for the curated catalog on OpenRouter accounts.

- **scope** - Fully transient - rows snapshot at open, nothing persists. The highlight seeds to the running model - matched by requested id, then resolved id, case-insensitively - and falls back to row 0 when the running model is not among the rows.

## Account picker (`/account`)

*visible: when `/account` runs AND the active session is idle (`runtime_session_state == Idle`). Mid-turn it is a no-op with a red system notice ("Finish or cancel the current turn before switching accounts."). A transient centered overlay drawn over whatever view is active.*

Switch the live session to a different account for its project and keep the SAME conversation. The overlay lists the project's allowed accounts (its `[[orgs]].accounts` pin, resolved via `Workspace::project_accounts_snapshot`), each row showing the current marker `●`, the account name, a budget block whose shape follows the account's `provider`, and a trailing status tag: `usable` in green, or one of two red reasons - `limit hit` when a plan window is at its cap and still resetting, `auth failed or expired` when the last probe was throttled, rejected, or the credentials are gone, or the boot-time load bailed. The split matters because which reason can apply is keyed on the billing kind: only a window-billed account can saturate. A window-billed account (`anthropic`, `codex`, `zai`) renders `5h` + `7d` utilization coloured by proximity to the cap, plus a reset ETA shown **only** while that account is at its cap. An API-billed one (`openrouter`) has no window and, uncapped, no denominator, so it renders per-key spend instead: `d` / `w` / `m` for today, this week and this month. Those three come from the same per-key endpoint; account-wide balance is deliberately absent. Any column forge has no reading for renders `-` rather than a zero, and the empty columns follow the account's billing model, so an unprobed API account shows `$- d $- w $- m` rather than windows it does not have. Three states land there and they are not the same as a measured zero: no snapshot yet, a snapshot that carried no figure for that column (a documented steady state on the proxy path, and on the Anthropic path a 200 carrying only the session window), and a cached snapshot written under a different `provider` that no longer describes the account. The last of those also logs a warning naming the account, because a stale row survives a `forge.toml` edit and is re-seeded at every boot. Any account marked `experimental = true` in `forge.toml` is **excluded from every auto-assignment path** (leads, workers, and the round-robin fallback) but is offered here **globally** - unioned into the snapshot regardless of the project's org pin, so a manual switch is the only way it ever gets used. Experimental accounts render in a dim `EXPERIMENTAL` group below the regular rows, each carrying an amber `experimental` tag before its status; they are still probed, so a down one reads an unusable tag just like any account. Picking a row re-spawns the session under that account's `config_dir` and `claude --resume`s the same `session_id` - the account config dirs share `~/.claude/projects` via symlink, so nothing is copied; a `SessionReplaced` resets then re-seeds the chat and refreshes the account label. Picking the current account (or an unusable one) is allowed - the current one is a no-op close; an unusable one is shown red.

- **keys** - <kbd>↑</kbd> <kbd>↓</kbd> move the highlight (clamped, no wrap) · <kbd>Enter</kbd> switch the session to the highlighted account (a no-op close when it's already the current one) · <kbd>Esc</kbd> close. The overlay is modal - it captures every key while open, over chat and launchpad alike. Keyboard-only for v1.
- **data source** - `Workspace::project_accounts_snapshot(allowed, current)` returns owned `AccountRow`s (name, config_dir, is_current, `unusable: Option<Unusable>`, experimental, and an `AccountBudget`) so the picker holds a snapshot, not the `AccountStateMap` lock. `Unusable` is the why behind the tag: `Saturated` (a window at its cap, still resetting) renders `limit hit`, while `ProbeBlocked` and `Bailed` both render `auth failed or expired`. `AccountBudget` is the three-way the row shape follows: `Unknown` when no snapshot has landed OR the cached one does not match the account's `provider`, `Subscription` carrying 5h/7d utilization (each column optional) plus the reset ETA, `Api` carrying the three spend figures. The budget block is sized against the room actually left after the name and the status tag, and degrades - dropping the reset ETA, then the repeated `$`, then the spacing, then back to the monthly figure alone - rather than overflowing, because the paragraph does not wrap and an overrun is cut with no ellipsis. The amber `experimental` prefix gives way only after the budget block and the name column, and before the tag ever would, on a row too narrow to carry it beside the widest tag. It is a view type and is not persisted, which is why the discrimination lives here rather than on `UsageSnapshot`. Reuses the same rate-limit machinery the launchpad account panel renders: `AccountStateMap::{unusable_reason, is_experimental, usage, config_dir}` + the binding 5h / 7d window utilization. The offered set is the allow-list UNION every experimental account (deduped), stable-sorted so experimental rows trail. Reset ETA (`binding_reset_at`) is populated only for windows currently at their cap.
- **switch** - <kbd>Enter</kbd> dispatches `Command::SwitchAccount { key, account_display_name, launch_settings }`. The workspace handler (`spawn::handle_switch_account`) releases the current subprocess, then re-spawns + resumes the same `session_id` under the picked account's `config_dir` via the forced-account path of `get_agent_handle_with_spawn_key`. The re-spawn seeds `connected_once = true` so its first Connected emits `SessionReplaced`; a supersession-safe task cleanup keeps the stale predecessor from wiping the re-spawned session. Live workers and in-flight peer asks are not blocked (workers run under their own accounts; peer asks to the switched session expire on reconnect and are re-askable).
- **code** - `crates/forge-tui/src/app/account_picker.rs` (state + key handling: open / nav / commit / close) · `crates/forge-tui/src/ui/account_picker.rs::render` (centered overlay) · `/account` handler at `crates/forge-tui/src/app/slash/executors.rs::handle_account_submit` (idle-gate + snapshot) · `forge_workspace::Workspace::project_accounts_snapshot` + `AccountRow` · `forge_workspace::protocol::Command::SwitchAccount` + `spawn::handle_switch_account`.
- **color** - border: RUST_ORANGE · title (`Switch account · <project>`): RUST_ORANGE bold · account count: `DIM` · current marker (`●`): RUST_ORANGE · highlighted account name: RUST_ORANGE bold · other names: default fg bold · `5h` / `7d` labels and the `d` / `w` / `m` period letters: `DIM` · the `-` in an empty `5h` / `7d` column: `DIM`, while the `$-` of an empty spend column keeps the spend colour so the three periods stay one row · window percentages by proximity to cap: green under ~70, yellow under 100, red at the cap · spend amounts: green flat, with no threshold colouring, because an uncapped key has no cap to be near · the `-` on an unprobed row: `DIM` · reset ETA (`⟳ resets …`): yellow · `usable` tag: green · `limit hit` tag: red · `auth failed or expired` tag: red · `EXPERIMENTAL` group header: `DIM` bold · `experimental` tag: amber · footer hints: `DIM`.
- **scope** - Fully transient - the open/highlight state doesn't survive a session restart. v1 is manual only. The project's allowed accounts plus every experimental account are listed (experimental ones globally, since they are never auto-assigned); no account management / editing `forge.toml` from the picker.

## Dictate overlay (`/dictate`)

*visible: when `/dictate` runs in the chat view. No gating on turn state - the dialog only dispatches workspace-state commands. A transient centered overlay drawn over whatever view is active.*

Session-scoped overrides for the dictation normalizer's three prompt axes, plus an input-device pick shared by every session, in the `/account` picker's chrome: 62 columns, `Borders::ALL` in RUST_ORANGE, a header line with a right-justified note, dim group headers that never take a highlight index, and a footer of key hints. The three groups map onto `forge-dictate`'s `Styling` / `Structure` / `Context`, with the crate's own vocabulary: `VOICE` carries casual / semi-casual / semi-formal / formal, `STRUCTURE` prose / `may bullet a list`, and `DESTINATION` plain text / `email layout`. The row labels are permissions, not promises - the model may decline, and the three-line note above the key hints says so. The `●` marks the value IN FORCE - the session override where one is set, the crate default otherwise (voice semi-formal, structure prose, destination plain text) - and a session-set row adds a DIM `· this session` suffix naming the source. The dialog reads state, because `INPUT DEVICE` is its own block below the groups (never a fourth axis): a `Device: <name>` readout row whose right-justified tag says where the value came from - `configured default (forge.toml)` DIM, `active until restart` in RUST_ORANGE, or `not present` in the error colour. The device pick is the `/spinner` shape: the `forge.toml` `[dictate] device` key is the durable pin and the default shown, a pick overrides it for every session, and a restart reverts to the key. <kbd>Enter</kbd> on the Device row opens pick mode (same chrome; header `Input device` with the right note `reverts on restart`): `System default` leads as the unpin row (tagged `no pin · now: <default name>`), the enumerated inputs follow by name with the system-default one tagged `system default input`, and the in-force row carries the `●`. A pin whose device no longer enumerates trails DIM and unreachable by its raw id with a red `not present · pinned in forge.toml` tag - nothing is in force, so the two-line red note replaces the standard note and the footer drops the `● in force` legend; a machine with no inputs (or a failed enumeration) draws `No input devices found.` with its hints and an <kbd>Esc</kbd>-only footer. One `Reset all to defaults` row sits below the device block, DIM and unreachable when nothing is overridden; it clears the device pick along with the override axes - back to defaults means back to forge.toml - and there is no per-axis clear, so enter on an already-set row re-sets the same value. `k` / `ngram` are deliberately absent - the crate proves they change wall clock and nothing else, so a row for either could be set and would do nothing to the text.

- **data source** - Rows are derived on every read from live state: the axis markers read the workspace-echoed `DictateOverrides` on the `UiSession`, and the device readout reads the workspace-echoed pick on `App`, so markers, suffixes and tags cannot drift from what the workspace holds. <kbd>Enter</kbd> on an axis dispatches `Command::SetDictateOverride { key, update }` (one axis, or `Reset`); a device pick dispatches `Command::SetDictateDevice { key, pick }` with a `DictateDeviceChoice` of `System` or `Device(id)`. The axes apply to the session's `DomainSession` and echo back as `SessionUpdate::DictateOverrides`; the pick applies to workspace state shared by every session and echoes back as `SessionUpdate::DictateDevicePin`, which is what the markers read. ## Push-to-talk dictate key (`Right Cmd`)

*active: whenever `[dictate] bind` is not `off` and the terminal negotiated the kitty enhancement flags. No visual surface of its own - the visible outcomes are words at the composer caret, info-level system notices, and the composer's [status row and border handoff](./input.md) while a take is live.*

Hold to record, release to transcribe; a clean tap shorter than 300 ms instead engages a toggle, so press-start-press-stop works without a hold. The key is configurable via `[dictate] bind` (`right_cmd` default, `left_cmd`, `off`); on Linux and Windows the cmd equivalent is the right/left Control key, mirroring how the Cmd shortcuts accept Ctrl off macOS. The gesture itself is `[dictate] mode`: `auto` (the timing inference above), `toggle` (press starts, the next press stops, releases never stop), or `hold` (release always transcribes, however brief - no tap window). Detection depends on the kitty `REPORT_ALL_KEYS_AS_ESCAPE_CODES` flag, which forge negotiates at startup and re-sets on resize; a terminal or multiplexer that discards the flags is logged at boot AND surfaced as a warning row on the preflight Dictation section, because with the flags gone the key silently never arrives. While the dictate key is down, any other key marks the hold a chord (the key still dispatches normally, so Right Cmd + V still pastes) and a chorded release cancels the speculative recording instead of transcribing it. Bare modifier presses and releases are consumed app-wide so they cannot tear down autocomplete or disturb a queued paste burst, and held keys arrive as `Repeat` events, which are dispatched like presses. With `[dictate]` disabled the key is dead. A press while dictation is ENABLED but not usable (the engine still loading, a device that will not open) is refused with a notice naming the cause. A take can be started from every text surface, not just the chat composer - the diff overlay, the prompt dock, and the plugins view each carry the pulsing circle blip on a fixed chrome spot (the key-hints bar, the dock's footer hint row, the sub-tab strip) while a take is live, and the first <kbd>Esc</kbd> on any of them abandons the take before that surface's own Esc semantics fire. An explicit save or submit of the host editor (<kbd>Enter</kbd> on the comment editor, <kbd>Ctrl+Enter</kbd> on the finish-review modal) abandons the take too - the user submitted without the words - while a passive landing stamps a DIM "dictated words landed here" notice on the draft it reached. The transcript lands in whichever editor of the dictating session is focused - the chat draft, a diff comment editor, the finish-review overview, or a plugins field - falling back to that session's chat draft when focus has moved to another session or no editor is open; a truncated take warns where its words landed (the overlay's notice line, the plugins status line, or the composer's notice row), and a notice without text covers no-audio (quiet room vs. structural silence worded differently), an empty transcript, a failure, and a mic claimed by another holder in the process.

- **keys** - <kbd>Right Cmd</kbd> press: start recording (nothing when one already runs) · release after a hold: finish and transcribe · release after a clean tap: keep recording · second press + release: finish · any other key while held: mark a chord, dispatch normally · chorded release: cancel the speculative recording, or leave a toggled recording running.
- **code** - `crates/forge-tui/src/app/dictate_key.rs` (key classification + dispatch) · `crates/forge-tui/src/app/events.rs::handle_terminal_event` (interception ahead of dispatch) · `crates/forge-workspace/src/dictate.rs::handle_dictate_start / handle_dictate_stop` (generation-tracked capture lifecycle on the stop channel, per-session `NormalizeOptions` merge at submit) · `protocol::{Command::DictateStart, Command::DictateStop}` · the `SessionUpdate::DictateStarted / DictateLevel / DictateEnded` reducers in `crates/forge-tui/src/app/events/client.rs` (indicator + landing) · `crates/forge-tui/src/app.rs::keyboard_enhancement_flags`.
- **scope** - The 300 ms tap/hold boundary is the one invented constant. The status row, its normalized meter and the border handoff are the composer indicator work; this surface only starts and ends captures and lands their outcomes.
