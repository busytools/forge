forge composer · the input surface and its states

The TUI's composer is not one widget. It is a text box, a hint slot, an autocomplete surface, a dictation status row and a prompt dock that morphs the whole thing. Below is each of those, redesigned for the web rather than ported.

The box

Web-native here means: no prompt character (the border is the identity), a send affordance that appears with content, and the hint as a line above rather than a character-cell row. Slash commands keep their magenta, because that is a real distinction.

Dictation

The TUI draws a 26-cell character meter and a dB figure. The web can do the same job honestly with a level bar that has real resolution, and can show the settled words landing as they arrive rather than only counting them. The row still lives inside the box, grows it by one line, and collapses when the take resolves.

The dictation panel

The microphone is the door rather than the trigger: pressing it shows what dictation is set to, and nothing on the page starts a take - the push-to-talk key is the trigger, which is the terminal's own shape. The panel is not a port of the terminal's overlay: the axes and their values are the same, and the form is the web's - each axis is a short exclusive set, so each is a row of chips rather than a list of rows.

The in-force chip is filled and outlined as well as coloured, so the state is not carried by hue alone.

Two rows are stated rather than offered, because nothing in the core can set them. The mode and the input device are both configured in forge.toml and both live outside this page - the device's pick rides the home snapshot, and the mode has no command at all - so each says where it comes from and neither offers a click nothing could honour. The terminal's own overlay keeps the mode in the config too, so this is its shape rather than a compromise.

The device row is the one that has to say when it goes back: a pick moves the process's input for the rest of the run, so the row says it reverts on restart and that the config's own device comes back - which is what happens rather than merely that it is temporary.

The prompt dock

The part that matters most, and the part the web can do better than a character grid. The box morphs into the prompt: the panel IS the box, so it carries the same ring, and your eye is already in that slot - a permission request arrives where you were about to type rather than somewhere else on the screen. Everything inside stays quiet. One narrow gutter for the mark, one text column: the name is the row's own line at full size, and an option's description supports it a step down at the label size, so four options still read as a list. Your in-flight draft is held and restored around the whole thing.

The swatches above carry the same declarations the box and the panel read rather than a copy of them, so a state cannot drift from its own drawing. What the panel is DOING wins over focus, and at rest the ring answers whether the keyboard is here - which is why the state is on the ring rather than on a label.
