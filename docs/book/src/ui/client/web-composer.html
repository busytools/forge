forge composer · the input surface and its states

The TUI's composer is not one widget. It is a text box, a hint slot, an autocomplete surface, a dictation status row and a prompt dock that morphs the whole thing. Below is each of those, redesigned for the web rather than ported.

The box

Web-native here means: no prompt character (the border is the identity), a send affordance that appears with content, and the hint as a line above rather than a character-cell row. Slash commands keep their magenta, because that is a real distinction.

Autocomplete

Four triggers, one popover shape. Each row carries the real icon for its kind rather than a character-cell prefix, the matched span is highlighted, and the cap is shown in the header so a truncated list never reads as the whole list. The / list is the one with two sources: forge's own commands lead, the ones the CLI advertises follow under their own heading, and a query drops the headings and leaves the order.

Dictation

A take draws as one card on the box's top-right corner rather than a row inside it, so a running take never moves the draft. The card is the dot, the clock, the level graph, the ready tally, the frames, the bytes, the pace and the way out — and while the take transcribes, the graph's slot becomes the section bar: a tick per section up to eight, then a fill with the count in words, because a section is a 30 to 60 second window and a take can hold sixty of them. As the box narrows, one reading leaves at a time from the left — clock, graph, ready tally, frames, bytes, pace — and the dot and the way out are never removed.

The dictation panel

The microphone is the trigger: pressing it starts or ends a take, and holding it (or Shift+Enter) opens what dictation is set to - a phone has no push-to-talk key, so a mic that only showed the settings would leave a finger no way to dictate. The panel is not a port of the terminal's overlay: the axes and their values are the same, and the form is the web's - each axis is a short exclusive set, so each is a row of chips rather than a list of rows.

The in-force chip is filled and outlined as well as coloured, so the state is not carried by hue alone.

One row is stated rather than offered, because nothing in the core can set it. The mode is configured in forge.toml and has no command at all, so it says where it comes from rather than offering a click nothing could honour. The terminal's own overlay keeps the mode in the config too, so this is its shape rather than a compromise.

The axes and the input are this page's own. A client that captures records from its own machine, so it lists its own inputs rather than asking the server for its. Both are remembered per seat on this machine, and the values the reset row returns to are the ones forge.toml set, which reach the client in the greeting.

The model rows are a second stated row and a second door. Transcribing and cleanup are what a take runs through, so the panel says which model each role holds, off the same read the models page draws. A role forge.toml sets is stated the way MODE is - the file and the key - because the core refuses the load. A role the config does not set opens a list of the models this machine can put there, and the press is the same activation the models page dispatches. Installing more is the models page's job, and the note under a one-model list says so.

The prompt dock

The box morphs into the prompt: your eye is already in that slot, so a permission request arrives where you were about to type rather than somewhere else on the screen. Each kind says what it is: a question draws its own words with the batch as marks, a permission draws the subject it is about with its actions as buttons, and a held post draws the body that would go out. The one row that takes words is always drawn, carries the mic, and is where a take's words land. Your in-flight draft is held and restored around the whole thing.
