forge composer · the input surface and its states

The TUI's composer is not one widget. It is a text box, a hint slot, an autocomplete surface, a dictation status row and a prompt dock that morphs the whole thing. Below is each of those, redesigned for the web rather than ported.

The box

Web-native here means: no prompt character (the border is the identity), a send affordance that appears with content, and the hint as a line above rather than a character-cell row. Slash commands keep their magenta, because that is a real distinction.

Autocomplete

Four triggers, one popover shape. Each row carries the real icon for its kind rather than a character-cell prefix, the matched span is highlighted, and the cap is shown in the header so a truncated list never reads as the whole list. The / list is the one with two sources: forge's own commands lead, the ones the CLI advertises follow under their own heading, and a query drops the headings and leaves the order.

Dictation

The TUI draws a 26-cell character meter and a dB figure. The web can do the same job honestly with a level bar that has real resolution. The row still lives inside the box, grows it by one line, and collapses when the take resolves, and the settled count is the terminal's own string — shown in the recording phase too, where the terminal has always had it.

The dictation panel

The microphone is the door rather than the trigger: pressing it shows what dictation is set to, and nothing on the page starts a take - the push-to-talk key is the trigger, which is the terminal's own shape. The panel is not a port of the terminal's overlay: the axes and their values are the same, and the form is the web's - each axis is a short exclusive set, so each is a row of chips rather than a list of rows.

The in-force chip is filled and outlined as well as coloured, so the state is not carried by hue alone.

One row is stated rather than offered, because nothing in the core can set it. The mode is configured in forge.toml and has no command at all, so it says where it comes from rather than offering a click nothing could honour. The terminal's own overlay keeps the mode in the config too, so this is its shape rather than a compromise.

The axes and the input are this page's own. A client that captures records from its own machine, so it lists its own inputs rather than asking the server for its. Both are remembered per seat on this machine, and the values the reset row returns to are the ones forge.toml set, which reach the client in the greeting.

The prompt dock

The part that matters most, and the part the web can do better than a character grid. The box morphs into the prompt: your eye is already in that slot, so a permission request arrives where you were about to type rather than somewhere else on the screen. Options are clickable rows with the real icon for their meaning, the keyboard still works, and your in-flight draft is held and restored around the whole thing.

The words being approved are shown in full, because a summary is not what goes out. The head names Post or Reply, the workspace, the conversation and the thread, and the conversation is Slack's own name for it rather than a # the panel made up: a DM's label is the partner's user id. A draft that leaves the core without your answer here - another view took it, or it expired - stands this dock down and leaves a line in its place saying which ending it was.
